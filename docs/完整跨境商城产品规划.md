# 完整跨境商城 · 产品规划

> 目标：在现有 Boot3 / Vue3 / Redis / RabbitMQ 工程上，升级为可演示的 **完整跨境电商业务系统**。  
> **每次修改先参考**：成熟商城参考实现（对照用，不在本公开仓库内）。先看它的分层、订单状态机、秒杀、支付回调，再改本仓的商品、购物车、下单、支付和履约。  
> 参考方式：对照模式和边界，不改 SpringMall，不整仓拷贝；本仓品牌是跨境商城，新表用 `cb_`。  
> 客服可选对接：`spring-ai-crossborder-chatbot`（后期 Agent 只读查单）。客服自身的改造不看 SpringMall，改客服前先看 客服参考实现（不在本仓库）。

---

## 1. 一句话定位

**跨境商城** = 面向消费者的跨境零售站点：浏览海外好物 → 加购 → 下单支付 → 履约与售后；后台可管商品/订单；可选智能客服查单。

与当前底座差异：

| 现状（课设升级版） | 目标产品 |
|--------------------|----------|
| 本地「店铺 + 探店笔记」 | 跨境「商品/SKU + 交易」 |
| 优惠券秒杀为主交易 | 普通订单 + 秒杀活动并存 |
| 社区 Feed 是主场景 | 社区降为可选增值；交易是主路径 |

---

## 2. 角色与端

| 角色 | 端 | 职责 |
|------|-----|------|
| 买家 C 端 | `crossborder-mall-frontend` 用户域 | 注册登录、逛商品、购物车、下单支付、我的订单、地址、售后入口 |
| 运营/管理员 | 同前端管理域或 `/admin` | 商品/分类/库存、订单发货、秒杀活动、简单看板 |
| 系统 | 后端单体 | 库存、订单状态机、超时关单、支付回调（可先模拟支付） |
| 客服 Agent（可选） | 兄弟项目 | 只读开放 API 查订单上下文 |

## 3. 业务模块（必须有）

### 3.1 商品域（P1）

- 分类（树或一级即可）
- 商品 SPU + SKU（至少：规格文案、价格、库存、主图）
- 上下架、列表筛选、详情
- Redis 商品缓存（可延续逻辑过期思路）

### 3.2 交易域（P2）

- 收货地址 CRUD
- 购物车（加购、改数量、勾选）
- 下单：校验库存 → 扣减 → 生成订单（待支付）
- 订单状态：`UNPAID → PAID → SHIPPED → COMPLETED / CANCELLED`
- 超时关单：RabbitMQ 延迟/TTL+DLX（参考 SpringMall）

### 3.3 支付域（P2）

- **先做模拟支付**（一键支付成功，改订单状态）
- 预留支付宝/微信/Stripe 回调入口（可后接）

### 3.4 营销域（P3）

- 把现有「优惠券秒杀」升级为「秒杀活动」挂商品 SKU
- 或保留 voucher 表作优惠券，另建 seckill_activity

### 3.5 用户域（已有，P1 补齐）

- 短信/验证码登录（已有 JWT）
- 个人资料、地址簿

### 3.6 内容域

探店笔记、关注 Feed、签到已从前后端删除，不再作为买家秀保留。

### 3.7 客服对接（另一条链路）

不在跨境商城这次改造里做。改智能客服前先看 客服参考实现（不在本仓库）。

## 4. 数据模型（目标表）

在库 `crossborder_mall` 中 **新增**（旧 `tb_shop` / `tb_blog` 可暂留兼容，前端主路径不再依赖）：

| 表 | 说明 |
|----|------|
| `cb_category` | 商品分类 |
| `cb_product` | 商品 SPU |
| `cb_product_sku` | SKU：价格、库存、规格 |
| `cb_cart_item` | 购物车行 |
| `cb_address` | 收货地址 |
| `cb_order` | 订单头 |
| `cb_order_item` | 订单行 |
| `cb_payment` | 支付单（模拟渠道） |
| `cb_seckill_activity` | 秒杀活动（可后期） |

命名前缀 `cb_` = crossborder，与课设 `tb_` 区分，避免混写踩坑。

## 5. API 前缀约定

统一：`/api/v1/**`，响应 `{ code, message, data }`。

| 前缀 | 说明 |
|------|------|
| `/api/v1/auth/**` | 登录注册 |
| `/api/v1/categories/**` | 分类（公开读） |
| `/api/v1/products/**` | 商品（公开读） |
| `/api/v1/cart/**` | 购物车（登录） |
| `/api/v1/addresses/**` | 地址（登录） |
| `/api/v1/orders/**` | 订单（登录） |
| `/api/v1/payments/**` | 支付 |
| `/api/v1/admin/**` | 管理端 |
| `/api/v1/open/agent/**` | 客服只读（可选） |

旧接口 `/api/v1/shops/**`、`/blogs/**` 等：过渡期保留，文档标注 **deprecated**。

## 6. 前端信息架构

```
/                 首页（跨境好物推荐）
/products         商品列表
/products/:id     商品详情 → 加购/立即购买
/cart             购物车
/checkout         确认订单
/orders           我的订单
/orders/:orderNo  订单详情（支付/联系客服）
/addresses        地址管理
/login
/admin/*          管理后台（商品、订单）
```

社区笔记入口已删除，首页只保留商品和秒杀。

## 9. 与 SpringMall 的取舍

| 借鉴 | 裁剪 |
|------|------|
| 分层、Result、Security、订单状态机 | 不必一次接齐三方支付 |
| 购物车 + 下单 + 库存扣减 | SKU 规格可先做「单规格/简单规格串」 |
| MQ 超时关单 | 秒杀可沿用现有 Lua+MQ，再映射到 SKU |
| 管理端发货 | 复杂促销引擎不做 |
