# 对齐 SpringMall · 业务缺口

**改造时建议先对照** 成熟商城参考实现（对照用，不在本公开仓库内）。

补缺口或改已对齐能力时：先在 SpringMall 里确认买家交易、管理端、支付和库存原来怎么做，再改 `crossborder-mall`。参考仓不改、不整页搬代码；本仓按跨境商城已有接口和 `cb_` 表补齐。

## 结论

买家交易闭环、商品缓存、商品秒杀（Lua + MQ）和管理端核心能力已经落地。真实三方支付仍不做。

## 已对齐

| 能力 | 状态 |
|------|------|
| 分类 / 分类树 / 关键词搜索 | ✅ |
| SKU、上下架、商品详情缓存 | ✅ 逻辑过期 + 空值防穿透，挂在商品上 |
| 购物车、地址、下单、确认收货 | ✅ |
| 模拟支付 + 支付单 | ✅ 渠道名可记 ALIPAY/WECHAT/STRIPE，不调用三方 |
| 超时关单、取消回库存 | ✅ RabbitMQ TTL + DLX |
| 管理端商品、分类、订单、看板、秒杀 | ✅ |
| 秒杀预热、Lua 扣库存、一人一单、异步落单、结果查询 | ✅ |
| JWT 登录、退出拉黑 | ✅ 仍是手机验证码，不是用户名密码 |

## 明确不做

- 真实支付宝 / 微信 / Stripe 的下单、回调、退款、掉单查单
- 后台用户封禁、忘记密码、订单归档
- SSE 秒杀库存条
- 客服只读查单（另一条链路）
