# 业务层

业务层在 `service` / `service.impl`。接入层进来的请求在这里变成「改库、改缓存、发 MQ」的完整用例。

## 服务一览

| 接口 | 实现 | 职责 |
|------|------|------|
| `AuthService` | `AuthServiceImpl` | 发码、登录、me、登出拉黑 |
| `UserService` | `UserServiceImpl` | 资料 |
| `ProductCatalogService` | `ProductCatalogServiceImpl` | 分类 / 商品列表与详情；详情走逻辑过期缓存；`evictProduct` |
| `CartService` | `CartServiceImpl` | 购物车；失效 SKU 软展示，不拖垮列表 |
| `AddressService` | `AddressServiceImpl` | 收货地址、默认地址、归属校验 |
| `MallOrderService` | `MallOrderServiceImpl` | 从购物车下单、买家取消 / 确认、管理发货取消、超时关单、支付成功标记；库存 CAS；注册延迟关单 |
| `PaymentService` | `PaymentServiceImpl` | **模拟支付**：锁订单行 → 写 `cb_payment` → CAS `UNPAID→PAID` |
| `SeckillActivityService` | `SeckillActivityServiceImpl` | 活动查询、预热、Lua 下单、结果查询、限流 |
| （落库） | `SeckillOrderPersistService` | MQ 消费后的幂等落库、`afterCommit` 写结果键与关单消息 |

## 订单状态机

状态常量在 `common.OrderStatus`：

```text
UNPAID ──► PAID ──► SHIPPED ──► COMPLETED
   │         │
   └─────────┴──► CANCELLED
```

非法跃迁抛业务异常。支付成功与超时关单都用 CAS / 状态断言互斥。

## 普通下单要点

1. 校验地址归属、勾选购物车行。  
2. 扣 SKU 或 SPU 库存（条件更新）。  
3. 写 `cb_order` + `cb_order_item`，清已选购物车。  
4. 发延迟关单消息（默认 TTL 约 15 分钟，见 `mall.order.ttl-ms`）。  
5. 支付：`FOR UPDATE` 订单 → 写支付单 SUCCESS → CAS 改为 PAID。  
6. 关单：仅当仍是 UNPAID 时改为 CANCELLED 并回库存；秒杀单还要回补 Redis 名额与一人一单集合。

## 秒杀要点（编排在业务层，执行分在异步层）

1. 管理端预热：`SETNX seckill:stock:{id}`。  
2. 下单：限流 → 调 Lua（扣库存 + `SADD` 一人一单）→ 发 MQ；发失败则回补 Redis。  
3. 立刻返回排队态；前端轮询 `seckill:result:{activityId}:{userId}`。  
4. 落库细节见 [异步层](异步层.md)。

## 这一层不做什么

- 不渲染 Vue 页面  
- 不在 controller 里堆 SQL  
- 不接真实三方支付回调
