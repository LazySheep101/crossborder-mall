# 异步层

异步层处理「请求已经返回，但工作还在后台继续」的两件事：秒杀订单落库、订单超时关单。代码在 `com.crossborder.mall.mq`，Lua 脚本在 `classpath:seckill.lua`。配置在 `config.RabbitMQConfig` 与 `mall.seckill.*` / `mall.order.*`。

## 秒杀链路

| 组件 | 作用 |
|------|------|
| `resources/seckill.lua` | 原子：库存减一 + 用户加入已下单集合；失败返回错误码 |
| `SeckillOrderProducer` | 发布到 `mall.seckill.exchange`，路由键 `seckill.order` |
| 队列 | `mall.seckill.order.queue` |
| `SeckillOrderConsumer` | 消费消息，调用 `SeckillOrderPersistService` |
| `SeckillOrderPersistService` | 幂等键 `seckill:msg:done:{requestId}`；落待支付订单；**事务提交后**写结果键并注册延迟关单；失败回补 Redis |

前端轮询：`GET /api/v1/seckill-activities/{id}/result`。

要点：

- 先 Lua 再 MQ：高并发下先抢名额，落库异步化。  
- MQ 发送失败必须回补库存与集合，否则名额泄漏。  
- 结果键放在 `afterCommit`，避免「结果已是 SUCCESS，库事务却回滚」。

## 超时关单链路

| 组件 | 作用 |
|------|------|
| `OrderCloseProducer` | 下单成功后发到延迟交换机 |
| 延迟队列 | `mall.order.delay.queue`，`x-message-ttl` = `mall.order.ttl-ms`（默认 900000 ms） |
| DLX | 到期进入 `mall.order.process.exchange` → `mall.order.close.queue` |
| `OrderCloseConsumer` | 调 `MallOrderService.closeIfUnpaid` |

`closeIfUnpaid` 仅在订单仍为 `UNPAID` 时取消并回库存；已支付订单忽略，与模拟支付 CAS 互斥。

## 这一层不做什么

- 不对浏览器直接暴露队列名  
- 不在消费者里写 HTTP 响应  
- 不替代业务层的状态机规则
