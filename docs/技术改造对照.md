3. 不改 SpringMall，不整文件搬过来。本仓包名是 `com.crossborder.mall`。

## 2. 认证改造

| 课设原方案 | 跨境商城 |
|------------|----------|
| UUID Token 存 Redis Hash | JWT（jjwt） |
| 拦截器 | `JwtAuthenticationFilter` + `SecurityFilterChain` |
| 退出删 Redis Token | 退出把当前 JWT 写入 `jwt:blacklist:`，过期时间与 token 剩余寿命一致 |
| 手机验证码登录 | 保留。验证码仍进 Redis，发码按手机号限流 |

公开路径：`/api/v1/auth/code|login`、商品/分类/秒杀活动列表与详情、健康检查。下单和秒杀结果查询需要登录。

---

## 3. 商品缓存（从店铺缓存迁过来）

| 能力 | 说明 |
|------|------|
| 逻辑过期 | 商品详情 `cache:product:{id}`，过期后互斥锁重建，未抢到锁返回旧值 |
| 穿透 | 不存在或下架的商品写入空串，短 TTL |
| 失效 | 管理端改商品、SKU、上下架，以及下单扣库存、取消回滚时删除该 key |

附近店铺 GEO、店铺类型列表不再使用。

---

## 4. 秒杀：优惠券课设 → 商品活动

| 跨境商城 | SpringMall | 落地 |
|----------|------------|------|
| `activityId` | `activityId` | `cb_seckill_activity` 挂商品/SKU |
| Lua 扣 Redis 库存 + 一人一单 | 分桶/单 Key Lua | `seckill.lua` |
| RabbitMQ 异步生成待支付订单 | 异步下单 | `mall.seckill.*` |
| 返回 QUEUING，再查结果 | 结果查询 / SSE | `GET /api/v1/seckill-activities/{id}/result` |
| 上线或「预热库存」写入 Redis | preheat | `POST /api/v1/admin/seckill/{id}/preheat` |
| 取消/超时关单 | 库存回补 | 回补商品库存、活动库存和 Redis 名额 |

配置前缀：`mall.seckill.*`。落库失败会把 Redis 库存和已下单用户加回去，并把结果写成 `FAIL`。

## 5. 前端

品牌文案：**跨境商城**。目录：`crossborder-mall-frontend`。

视觉对齐 SpringMall 的 Saleor 黑白编辑风：`assets/styles/{variables,reset,common}.scss`、Inter 字体、黑主色 Element Plus 主题、买家 `UserLayout`（通告栏 / 居中 Logo / 购物车角标 / 页脚）与管理端 `AdminLayout`（侧栏）。公共 `Loading` / `Empty`、秒杀 `CountdownRoller`。

导航只留首页、商品、秒杀、购物车、订单、我的。店铺、买家秀、优惠券页已删除。秒杀详情先排队再跳支付。退出会调 `/auth/logout`。

---

## 6. 已去掉的课设内容

店铺、店铺类型、GEO、探店笔记、关注 Feed、点赞、签到 Bitmap、优惠券秒杀。这些表由 `db/cb_mall_drop_legacy.sql` 删除。登录用户表 `tb_user` 保留。

## 7. 本轮不做

- 真实支付宝 / 微信 / Stripe 下单、回调、退款。支付页只做模拟支付，渠道名写入 `cb_payment`。
- 客服只读查单。那是智能客服链路，不在本仓这次改造里。
- 不把 SpringMall 整套文件搬进来。以后每次改跨境商城，仍然先对照 成熟商城参考实现。
