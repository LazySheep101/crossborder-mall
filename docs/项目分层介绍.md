# 跨境商城 · 项目分层介绍

产品名：**跨境商城**。仓库目录：`crossborder-mall`。

这份文档回答四件事：

1. 系统有哪些层  
2. 每一层代码在哪、负责什么、不负责什么  
3. 一条下单 / 秒杀请求经过哪些层  
4. 其它 md 各管哪一层  

整体叙事与演示数据见根目录 [架构说明.md](../架构说明.md)。怎么启动看 [README.md](../README.md)。

---

## 1. 总览

```text
买家端 SPA / 管理端 SPA（Vue 3 · Pinia · Element Plus）
        │  /api  →  Vite 代理到后端
        ▼
┌──────────────────────────────────────────────────────────┐
│  controller          买家 API + /admin/** 管理 API         │
│  security            JWT 解析、黑名单、角色（USER/ADMIN）   │
├──────────────────────────────────────────────────────────┤
│  service             商品、购物车、地址、订单、支付、秒杀   │
│  mq                  秒杀异步落库、订单延迟关单             │
│  utils / CacheClient 逻辑过期缓存、分布式锁、限流、ID 工人 │
├──────────────────────────────────────────────────────────┤
│  mapper / entity     MyBatis-Plus ↔ MySQL（crossborder_mall）│
└──────────────────────────────────────────────────────────┘
        │
        ├─ MySQL          商品 / 订单 / 支付 / 秒杀活动
        ├─ Redis          验证码、商品缓存、秒杀库存与结果、JWT 黑名单
        └─ RabbitMQ       秒杀队列、订单 TTL 关单
```

依赖方向：页面 → controller → service → mapper / Redis / MQ。  
`mq` 消费者只回调 service，不反向依赖 controller。

**支付是模拟落库**，不接真实支付宝 / 微信。秒杀：Redis Lua + MQ 异步落单 + 一人一单。

## 2. 使用层：两端入口

| 端 | 谁 | 地址 | 登录 |
|----|----|------|------|
| 买家 | 用户 | http://localhost:3000 | 手机号 + 验证码（码在后端日志） |
| 管理 | 管理员 | http://localhost:3000/admin | 同上；手机号须在 `mall.admin-phones` |

默认配置里管理员手机号可用环境变量 `ADMIN_PHONE` 覆盖。

买家主路径：商品 → 购物车 → 确认订单 → 模拟支付 → 订单详情。  
秒杀路径：秒杀列表 → 选地址抢购 → 轮询结果 → 支付。

详情：[层/使用层.md](层/使用层.md)

## 3. 各层职责与文档

| 层 | 目录 | 负责 | 不负责 | 细分文档 |
|----|------|------|--------|----------|
| 使用 | `frontend/src/views` 等 | 浏览、加购、下单、支付、秒杀 UI；管理运营页 | 不直连 Redis / MQ | [使用层](层/使用层.md) |
| 接入 | `backend/.../controller` | `/api/v1/**` REST；统一 `Result` | 不写库存扣减细节 | [接入层](层/接入层.md) |
| 安全 | `security` + `SecurityConfig` | JWT、黑名单、`ROLE_ADMIN` | 不发短信真通道 | [安全层](层/安全层.md) |
| 业务 | `service` / `service.impl` | 登录、商品缓存、购物车、订单 CAS、模拟支付、秒杀 | 不渲染页面 | [业务层](层/业务层.md) |
| 异步 | `mq` + `seckill.lua` | 秒杀落库、延迟关单 | 不直接对浏览器暴露 | [异步层](层/异步层.md) |
| 缓存工具 | `utils` | 防穿透、逻辑过期、锁、限流 | 不替代业务事务 | [缓存与工具层](层/缓存与工具层.md) |
| 持久化 | `mapper` + `entity` + `db` | 表映射、CAS SQL、种子 | 不暴露 HTTP | [数据层](层/数据层.md) |

接口前缀一律 `/api/v1`。管理接口在 `/api/v1/admin/**`，需 `ROLE_ADMIN`。

后端包名：`com.crossborder.mall`。默认端口 **8081**；本机 `application-dev.yml` 常改用 **8088**（与前端 Vite 代理一致）。

## 4. 两条主链路怎么走

### 4.1 普通下单 + 模拟支付

```text
加购 → POST /cart
确认页 → POST /orders（扣库存、清已选购物车、注册延迟关单）
支付页 → POST /payments/mock
         → 订单行锁 FOR UPDATE
         → 写 cb_payment(SUCCESS)
         → CAS：UNPAID → PAID
超时未付 → MQ 延迟消息 → CAS：UNPAID → CANCELLED → 回库存
```

### 4.2 秒杀

```text
预热        Redis SETNX seckill:stock:{活动id}
下单        Lua：扣库存 + 一人一单集合
            → 发 MQ（失败则回补 Redis）
            → 返回 QUEUING
消费者      落库（幂等 requestId）
            → afterCommit 写结果键 + 延迟关单
前端        轮询 GET .../result → SUCCESS 再跳支付
```
