# 跨境商城 · 项目分层介绍

产品名：**跨境商城**。仓库目录：`crossborder-mall`。作者：lazysheep101。

这份文档只回答四件事：

1. 系统有哪些层  
2. 每一层代码在哪、负责什么、不负责什么  
3. 一条下单 / 秒杀请求经过哪些层  
4. 其它 md 各管哪一层

怎么启动看根目录 [README.md](../README.md)。


---

## 1. 总览

```text
买家端 SPA / 管理端 SPA（Vue 3 · Pinia · Element Plus）
        │  /api/v1  →  Vite 代理到后端
        ▼
┌──────────────────────────────────────────────────────────┐
│  controller          买家 API + /admin/** 管理 API         │
│  security            JWT 解析、黑名单、角色（USER/ADMIN）   │
├──────────────────────────────────────────────────────────┤
│  service             商品、购物车、地址、订单、支付、秒杀   │
│  mq                  秒杀异步落库、订单延迟关单             │
│  utils / CacheClient 逻辑过期缓存、分布式锁、限流、ID 工人 │
├──────────────────────────────────────────────────────────┤
│  mapper / entity     MyBatis-Plus ↔ MySQL（crossborder_mall）│
└──────────────────────────────────────────────────────────┘
        │
        ├─ MySQL 3306     商品 / 订单 / 支付 / 秒杀活动
        ├─ Redis 6379     验证码、商品缓存、秒杀库存与结果、JWT 黑名单
        └─ RabbitMQ 5672  秒杀队列、订单 TTL 关单
```

依赖方向：页面 → controller → service → mapper / Redis / MQ。  
`mq` 消费者只回调 service，不反向依赖 controller。

**支付是模拟落库**，不接真实支付宝 / 微信。秒杀保留：Redis Lua + MQ 异步落单 + 一人一单。

## 2. 使用层：两端入口

| 端 | 谁 | 地址 | 登录 |
|----|----|------|------|
| 买家 | 用户 | http://localhost:3000 | 手机号 + 验证码（码在后端日志） |
| 管理 | 管理员 | http://localhost:3000/admin | 同上；手机号须在 `mall.admin-phones` |

默认管理员手机号由配置项 `mall.admin-phones` / 环境变量 `ADMIN_PHONE` 决定（示例种子常用 `13800138000`）。

买家主路径：商品 → 购物车 → 确认订单 → 模拟支付 → 订单详情。  
秒杀路径：秒杀列表 → 选地址抢购 → 轮询结果 → 支付。

## 3. 各层职责

| 层 | 目录 | 负责 | 不负责 |
|----|------|------|--------|
| 买家页 | `frontend/src/views`（非 admin） | 浏览、加购、下单、支付、秒杀 UI | 不直连 Redis / MQ |
| 管理页 | `frontend/src/views/admin` | 商品 / 分类 / 订单 / 秒杀运营 | 不绕过后端鉴权 |
| 路由守卫 | `frontend/src/router` | `requiresAuth` / `requiresAdmin`；进后台会 `fetchMe` | 最终权限以后端为准 |
| 接入 | `backend/.../controller` | `/api/v1/**` REST；统一 `Result` | 不写库存扣减细节 |
| 安全 | `security` + `config/SecurityConfig` | JWT、黑名单、`ROLE_ADMIN` | 不发短信真通道 |
| 业务 | `service` / `service.impl` | 登录、商品缓存、购物车、订单 CAS、模拟支付、秒杀 | 不渲染页面 |
| 异步 | `mq` | 秒杀落库、延迟关单消费 | 不直接对浏览器暴露 |
| 缓存工具 | `utils`（CacheClient、Lock、限流） | 防穿透、逻辑过期、锁、限流 | 不替代业务事务 |
| 持久化 | `mapper` + `entity` | 表映射、CAS SQL | 不暴露 HTTP |
| 存储 | MySQL / Redis / RabbitMQ | 见总览 | — |

接口前缀一律 `/api/v1`。管理接口在 `/api/v1/admin/**`，需 `ROLE_ADMIN`。

## 4. 两条主链路怎么走

### 4.1 普通下单 + 模拟支付

```text
加购 → POST /cart
确认页 → POST /orders（扣库存、清已选购物车、注册延迟关单）
支付页 → POST /payments/mock
         → 订单行锁 FOR UPDATE
         → 写 cb_payment(SUCCESS)
         → CAS：UNPAID → PAID
超时未付 → MQ 延迟消息 → CAS：UNPAID → CANCELLED → 回库存
```

支付与关单用 **CAS** 互斥，避免「已支付又被关单回库存」。

### 4.2 秒杀

```text
预热        Redis SETNX seckill:stock:{活动id}
下单        Lua：扣库存 + 一人一单集合
            → 发 MQ（失败则回补 Redis）
            → 返回 QUEUING
消费者      落库（幂等 requestId）
            → afterCommit 写结果键 + 延迟关单
前端        轮询 GET .../result → SUCCESS 再跳支付
```

结果键与关单消息都在 **事务提交后** 写，避免「轮询成功但订单还没提交」。

## 5. 代码层：目录对照

| 层 | 路径 |
|----|------|
| 前端买家 / 管理 | `crossborder-mall-frontend/src/views`、`views/admin` |
| 前端 API | `frontend/src/api` |
| 控制器 | `backend/.../controller`（含 `Admin*`） |
| 业务 | `backend/.../service`、`service.impl` |
| 秒杀落库 | `SeckillOrderPersistService` |
| MQ | `backend/.../mq` |
| 安全 | `backend/.../security` |
| Lua | `backend/src/main/resources/seckill.lua` |
| 建表 SQL | `backend/src/main/resources/db/` |

后端包名：`com.crossborder.mall`。单模块 Boot 进程，端口 **8081**。

## 6. 数据层

| 数据 | 位置 | 说明 |
|------|------|------|
| 用户 | `tb_user` / `User` | 手机号登录自动注册 |
| 分类 / 商品 / SKU | `cb_category`、`cb_product`、`cb_product_sku` | 商品详情走逻辑过期缓存 |
| 购物车 / 地址 | `cb_cart_item`、`cb_address` | 失效 SKU 软展示，不拖垮列表 |
| 订单 / 明细 | `cb_order`、`cb_order_item` | 状态：UNPAID→PAID→SHIPPED→COMPLETED / CANCELLED |
| 支付 | `cb_payment` | 仅模拟 SUCCESS |
| 秒杀活动 | `cb_seckill_activity` | DB 库存 + Redis 库存双轨 |
| Redis 关键键 | `seckill:stock:` / `seckill:order:` / `seckill:result:` / `jwt:blacklist:` / `cache:product:` | — |

建库脚本顺序见 [数据库初始化说明.md](./数据库初始化说明.md)；`docker-compose` 已按同序挂载 `cb_mall_*`。
